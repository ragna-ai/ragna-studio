A workflow is a chain of steps that RAGNA Studio runs automatically. Each step is a node on a canvas. Nodes are connected, and the output of one node becomes the input of the next. Use workflows to automate multi-step tasks with [agents](/agents), branching and text templates.

## Create a workflow

1. Open **Workflows** in the sidebar.
2. Click **New workflow**.
3. Enter a name and create it. The canvas opens.

The list shows each workflow as **Draft** or **Published**. A workflow with a schedule also shows when it runs (see [Triggers and schedules](/workflows/triggers)).

## Add nodes

Use **Add node** to put a node on the canvas. Click a node to open its settings in a side panel. The panel holds a **Label** and the node's configuration.

| Node          | What it does                                                                             |
| ------------- | ---------------------------------------------------------------------------------------- |
| **Trigger**   | Starts the workflow. Every workflow has exactly one. Manual or scheduled.                |
| **Agent**     | Runs an [agent](/agents) with a prompt. Pick a saved agent. An agent is required.        |
| **Team**      | A lead agent delegates work to specialist agents. See [Team node](/workflows/team-node). |
| **Condition** | Compares two values and sends the flow down a `true` or a `false` branch.                |
| **Transform** | Builds new text from a **Template**.                                                     |

The agent runs like it does in chat: with its own model, tools and settings. A workflow cannot be saved with an agent node that has no agent. A node in an older workflow without an agent fails the run with "Pick an agent for this node". Edit the node to fix it.

## Connect nodes

Drag from the handle of one node to the handle of another to connect them. Connections run in one direction. A workflow cannot contain loops.

Several nodes can follow one node. A node with several incoming connections waits until all of them are resolved.

## Pass data between nodes

Each node gets an input. This is the output of the previous node. The first node after the trigger gets the run input (see below). If several connections arrive, their outputs are joined with a blank line.

Write `{{input}}` in a prompt, template or condition field to insert that input. An unknown placeholder becomes empty text.

- **Agent**: the **Prompt** can use `{{input}}`.
- **Transform**: the **Template** can use `{{input}}`, for example `Summary:\n{{input}}`.
- **Condition**: **Left** and **Right** can use `{{input}}`.

The output of the last node is the output of the run. If the flow ends in several nodes, the output lists each one.

## Branch with a condition

A condition node compares **Left** with **Right** using one operator:

- equals
- notEquals
- contains
- isEmpty
- isNotEmpty

Two connections leave the node, labeled `true` and `false`. Connect each to the branch that should run. The other branch is skipped. A condition does not pass its own `true` or `false` on. The next node receives the content that came into the condition.

## Save, publish and run

Edits are a draft. Click **Save** to keep them. The editor shows **Unpublished changes** when the draft differs from the published version.

Runs always use the published version. Click **Publish** to make the draft the live version.

1. Click **Run** in the editor.
2. Optionally enter an **Input**. It becomes the input of the first node.
3. Click **Run published version**. If the workflow was never published, click **Publish & run**.

The dialog warns when a run uses an older published version than the latest edits. The run opens in a new view. See [Runs and traces](/workflows/runs).

## Why can't I save?

Save, **Publish** and **Publish & run** check the workflow first. A node with a problem gets a red border and a warning icon with the reason. The side panel shows the message next to the field.

Common causes:

- An **Agent** node has no agent picked.
- A **Team** node has no lead agent, or a member has no agent.
- A picked agent was deleted.
- The workflow was created before agents became required.

To fix it, click the marked node, pick an agent in the side panel and save again.

Renaming a workflow always works, even while a node has a problem.

Publishing also needs exactly one trigger and no loops.
