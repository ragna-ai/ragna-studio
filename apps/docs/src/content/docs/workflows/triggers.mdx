Every workflow starts at its trigger node. The trigger decides how runs begin. A run starts by hand or on a schedule.

## Trigger types

Select the trigger node and choose a **Trigger type**.

| Type         | Behavior                                                        |
| ------------ | --------------------------------------------------------------- |
| **Manual**   | The workflow runs when a user clicks **Run**. No configuration. |
| **Schedule** | The workflow runs by itself at the configured times.            |

## Set a schedule

1. Select the trigger node and set **Trigger type** to **Schedule**.
2. Choose a **Frequency**: **Hourly**, **Daily**, **Weekly** or **Custom**.
3. Set the **Time**. For weekly schedules, also set the **Day of week**.
4. For **Custom**, enter a **Cron expression**.
5. Check the **Timezone**. It defaults to the browser timezone.
6. Look at **Next runs**. It shows the next three run times.
7. **Save** and **Publish**.

A custom cron expression has five fields: minute, hour, day of month, month and day of week. For example, `30 8 * * 1-5` runs at 08:30 on weekdays. Seconds are not supported, so the shortest interval is one minute. The form shows **Invalid cron expression** when the text is not valid.

## When a schedule is active

Only the published version counts. A schedule starts when a workflow is published with a **Schedule** trigger. Editing the draft does not change it. If a version with a **Manual** trigger is published, or the workflow is deleted the workflow, the schedule stops.

To change a schedule, edit the trigger and publish again.

Runs started by a schedule are marked **Scheduled** in the run history. Runs started by hand are marked **Manual**. A scheduled run has no input, so `{{input}}` is empty in the first node.

## Overlap protection

A schedule never stacks runs. If the previous run is still pending or running when the next time arrives, RAGNA Studio skips that time. It does not catch up on missed times later.

## Scheduled runs act as their author

A scheduled workflow runs as its author. If the author can no longer open the workspace, or their account is removed, the schedule pauses. The workflow shows a **Schedule paused** badge. The schedule resumes when the author can run it again. Manual runs still work.

The badge explains: "The author can no longer run this workflow." There is no fallback to another person. See [Workspaces](/workspaces) and [Members](/workspaces/members) for how access works.

## After a restart

If the background services restart, RAGNA Studio restores all schedules from the published workflows. Nothing needs to be published again.

## Failed scheduled runs

A scheduled run that fails a node is retried like any other run (see [Runs and traces](/workflows/runs)). If it still fails, the next scheduled time starts a fresh run. A run stuck for too long is failed automatically, which frees the schedule. See [Runs and traces](/workflows/runs).
