The MCP connector lets an external AI app (an MCP client, such as Claude Desktop) work with a user's RAGNA Studio data on their behalf. Access is granted per resource type, such as datasets. Apps can read and write, but they cannot delete anything.

Nothing is shared until the user turns it on. Each user decides per resource type what the AI app may do, and can revoke access at any time.

<Aside type="note">
  The connector is off by default on the server. On a self-hosted instance, the instance operator
  must enable it and name the allowed apps first. See [Environment
  variables](/reference/environment-variables). If **MCP is not available** appears on the settings
  page, the server has not enabled it.
</Aside>

## Turn on MCP

1. Open the user menu and choose **MCP**.
2. Switch on **Allow external AI apps to access your account (MCP)**.

The **Connector URL** card appears. Turning MCP off later asks for confirmation, because it disconnects every connected app at once. After turning it on again, every app has to be reconnected.

## Supported resources

| Resource | Read                               | Read & write                                  |
| -------- | ---------------------------------- | --------------------------------------------- |
| Datasets | Find datasets and read their rows. | Create datasets, and add, edit and move rows. |

More resource types will follow.

## Choose what apps may do

Under **Resource access**, set a level for each resource type. Every type starts at **Off**.

| Level            | What the AI app can do                                             |
| ---------------- | ------------------------------------------------------------------ |
| **Off**          | Nothing. The AI app does not see this resource type.               |
| **Read**         | Find and read resources of this type.                              |
| **Read & write** | Everything in Read, plus create and change resources of this type. |

See [Supported resources](#supported-resources) for what each level allows per resource type. The level applies to all resources of that type in the connected workspace. Single resources cannot be picked. Changes take effect on the AI app's next request. The AI app does not need to reconnect.

## Connect Claude Desktop

1. On the MCP settings page, copy the **Connector URL** with the copy button.
2. In Claude Desktop, go to **Settings > Connectors > Add custom connector** and paste the URL.
3. Claude Desktop opens RAGNA Studio. Sign in if needed.
4. On the **Connect this app to your account** screen, choose a **Workspace**. The screen also shows what the AI app will be able to do.
5. Choose **Approve**. Choose **Deny** to cancel.

If MCP is off, the screen shows **MCP is turned off** and a link to the settings. Turn MCP on first, then connect again.

Each connection belongs to one workspace. To work in another workspace, revoke the connection and connect again.

## Rows written by an app

When an app adds or changes rows, RAGNA marks the origin. Datasets created by an app show **MCP** in the **Origin** column of the dataset list. Rows written by an app carry the note **Written by a connected app via MCP** in the dataset grid. RAGNA also records each write call per connection. Reads only update the **Last used** time.

See [Datasets](/content/datasets) for the grid.

## See and revoke connections

The **Connected apps** card lists each app with its **Workspace**, when it was **Connected** and when it was **Last used**. Choose **Revoke** next to an app and confirm. The AI app is disconnected immediately and has to connect again.

Turning MCP off under **Allow external AI apps to access your account (MCP)** revokes every connected app at once.

## How access is protected

An app can only be connected to an account by the owner of that account. The connection belongs to the user who is signed in when **Approve** is chosen. The AI app never sees the user's password or sign-in session.

<pre class="mermaid">{`
sequenceDiagram
  actor User
  participant App as AI app (MCP client)
  participant Studio as RAGNA Studio
  participant API as RAGNA API

  App->>API: Request without a token
  API-->>App: 401, with where to sign in
  App->>Studio: Open sign-in in the user's browser
  User->>Studio: Sign in with their own account
  Studio->>User: Consent screen: app, redirect, workspace, access
  User->>Studio: Approve
  Studio->>API: Save connection for this user, app and workspace
  Studio-->>App: Redirect back with a one-time code
  App->>API: Exchange the code for a token (PKCE)
  API-->>App: Token for this user and app only

  loop Every request
    App->>API: Tool call with the token
    API->>API: Check token, MCP on, connection exists, access level
    API-->>App: Result, limited to the connected workspace
  end

  User->>Studio: Revoke the AI app or turn MCP off
  Studio->>API: Delete connection, revoke tokens
  App->>API: Next tool call
  API-->>App: 401, reconnect required
`}</pre>

What this guarantees:

- **No user can connect an app to another user's account.** The consent screen requires the account owner's sign-in. A user who copies another user's connector URL goes through the same flow and has to sign in as themselves.
- **An app can't do more than its user.** The user can only pick a workspace they are a member of. The access levels on the MCP settings page limit the AI app further.
- **Each request is checked again.** The token alone is not enough. On every call, RAGNA checks that MCP is still on for the user and the connection still exists, and reads the current access levels.
- **Revoking takes effect immediately.** A user can revoke an app under **Connected apps**, or turn MCP off to revoke all of them. The AI app's next request fails, and it can't refresh its token. See [See and revoke connections](#see-and-revoke-connections).
- **Only allowed apps can ask.** The server only accepts apps that its operator has listed. Any other app is rejected before a consent screen is shown.

Users should approve a connection only if they started it themselves. The consent screen names the AI app and the host it redirects to after approval. If the request came from an unexpected link, the right choice is **Deny**.
