Go through this list before sharing RAGNA Studio.

## Network

- **Open only ports 80 and 443** in the firewall. The reverse proxy serves both domains on them.
- **Keep ports 3000 and 3010 on `127.0.0.1`.** The self-host override publishes them there. Don't change it to `0.0.0.0`, or RAGNA Studio is reachable without TLS.
- **Never publish the `webbrowser` service.** It fetches any URL an agent asks for. Exposed, it lets any user reach hosts inside the operator's network. It has no published port by default, keep it that way.
- **Postgres and Redis stay inside the Docker network.** They have no published ports either.

## Sign-in

- **Restrict who can sign in.** By default, every user with an account at the OAuth provider can sign in. Set `ALLOWED_LOGIN_EMAILS`, see [Configuration](/self-hosting/configuration#restricting-sign-up).
- **Serve both domains over https.** `NUXT_PUBLIC_API_BASE_URL` must be the https API URL.

## Secrets

- **Keep `.env` private.** It holds every secret. The installer creates it with mode `600`. Keep it out of version control.
- **Use generated secrets.** Never keep the placeholder values from `.env.example`.
- **Never rotate `BETTER_AUTH_SECRET`.** Encrypted data such as stored OAuth tokens becomes unreadable. Every session also ends.
- **Back up `BETTER_AUTH_SECRET` with the data.** A database backup is useless without it, see [Upgrades and backups](/self-hosting/upgrades-and-backups#backups).

## MCP

- **Leave `MCP_ENABLED` off unless it is needed.** When off, the MCP endpoint, its OAuth endpoints and the settings page don't exist.
- **List only trusted apps in `MCP_ALLOWED_CLIENT_IDS`.** Apps not on the list can't start a connection. See [MCP connector](/integrations/mcp#how-access-is-protected) for how users grant and revoke access.

## Storage

- **Only the images bucket is public-read.** The documents bucket stays private. See [Storage](/self-hosting/storage).
- **Limit the S3 key** to these two buckets.

## Updates

- **Stay on a current release.** Upgrade with `--upgrade`, see [Upgrades and backups](/self-hosting/upgrades-and-backups).
- **Verify images before an upgrade (optional).** From v0.6.7 on, every release image carries a signed build provenance attestation. It proves the image was built from this repository by the RAGNA Studio release workflow. Check it with the GitHub CLI, per image and version:

  ```bash
  gh attestation verify oci://ghcr.io/ragna-ai/ragna-studio-backend:0.6.7 -R ragna-ai/ragna-studio
  ```
