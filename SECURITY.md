# Security Policy

## Reporting a vulnerability

Please report vulnerabilities privately. Do not open a public issue.

- Use [private vulnerability reporting](https://github.com/ragna-ai/ragna-studio/security/advisories/new) on GitHub, or
- Email `security@ragna.io`.

Include a description of the issue and steps to reproduce it. The more detail you give, the faster we can fix it.

You can expect a first response within three business days.

## What we ask

- Keep the details confidential until a fix is released.
- Do not access, change, or delete data that is not yours.
- Do not run denial-of-service or social-engineering attacks.

## What you can expect

- We will confirm the report and keep you updated on progress.
- We will credit you in the release notes if you want to be named.
- We will not pursue legal action for good-faith research that follows this policy.
- You may discuss your findings publicly once users have had a reasonable time to update.

There is no bug bounty program at this time.

## Supported versions

Only the latest release receives security fixes. RAGNA Studio is self-hosted. Update by pulling the newer images and starting the stack again.

## Scope

This policy covers the code in this repository. Vulnerabilities in your own deployment, such as exposed ports or leaked `.env` files, are your responsibility. Vulnerabilities in third-party dependencies should be reported to their maintainers. Tell us too if RAGNA Studio is affected.
